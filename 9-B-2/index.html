Chapter 9 · Probability

Counting Outcomes

To find a probability you often need to count the outcomes, and there can be far too many to list. A tree shows why the counts multiply, and a row of slots turns that into a quick calculation for codes, line-ups and teams.

Basics you are here Undergraduate Masters

On this page

  • List outcomes systematically with a list, a two-way table or a tree diagram.
  • Use the multiplication principle: m ways and then n ways make m × n ways.
  • Count codes and passwords, where symbols can repeat (with repetition).
  • Count arrangements where order matters and nothing repeats, using the factorial n!.
  • Count combinations, groups where order doesn’t matter, by dividing out the repeats, and meet Pascal’s triangle.
  • Turn counts into probabilities: favourable ÷ total, from 9.B.1.

1Listing without missing any

You have 3 shirts and 2 pairs of pants. How many outfits? You could list them, but lists are easy to get wrong: you miss one or count one twice. The fix is to list systematically: take the first shirt and pair it with every pair of pants, then the second shirt, and so on.

For two choices, a two-way table does this automatically: shirts down the side, pants across the top, one outfit in each cell. For three or more choices, use a tree diagram. Each choice is a stage. Start from a single point, draw a branch for every option at stage 1, then from the end of every one of those branches, draw a branch for every option at stage 2, and so on. Every path from the root to a leaf is one outcome, and each appears exactly once.

2The multiplication principle

Look at the tree. Each of the 3 shirt branches splits into 2 pants branches: 3 × 2 = 6 paths. If each of those splits into 2 pairs of shoes, there are 6 × 2 = 12. That’s the multiplication principle (also called the fundamental counting principle):

\[ \text{if one choice can be made in } m \text{ ways and then another in } n \text{ ways, together they can be made in } m \times n \text{ ways.} \]

It works for any number of stages, and it lets you count without drawing anything. A bike lock with 3 dials of 10 digits has 10 × 10 × 10 = 10³ = 1000 codes. Because a digit can be used again, every dial has all 10 choices: that’s counting with repetition. Each extra character multiplies the count again, which is why longer passwords are so much safer.

3Order matters: arrangements

Eight runners race. How many ways can gold, silver and bronze be awarded? 8 runners could win gold. Whoever wins, only 7 are left for silver, then 6 for bronze: 8 × 7 × 6 = 336. This is counting without repetition, because nobody can win two medals. An ordering like this is an arrangement (also called a permutation), and here order matters: Ana gold and Ben silver is a different result from Ben gold and Ana silver.

Lining up all of 4 friends: 4 × 3 × 2 × 1 = 24 ways. A product counting all the way down to 1 is so common it has a name, n factorial, written n!: 4! = 24, 5! = 120, 10! = 3,628,800. Factorials grow astonishingly fast. A shuffled deck of cards can be in 52! ≈ 8 × 10⁶⁷ orders, so every proper shuffle is almost certainly an order no deck has ever been in before.

4Order doesn’t matter: choosing a group

Now choose a team of 2 from 5 friends. Counting in order gives 5 × 4 = 20, but the team {Ana, Ben} is the same as {Ben, Ana}: each team was counted twice, once for each order. So there are 20 ÷ 2 = 10 teams. A group chosen where order doesn’t matter is a combination. In general, count the arrangements, then divide by the number of ways to order each group, k!:

\[ \text{3 toppings from 8: } \frac{8 \times 7 \times 6}{3 \times 2 \times 1} = \frac{336}{6} = 56. \]

This number is called “8 choose 3”. The “choose” numbers fill Pascal’s triangle, where each number is the sum of the two above it.

5From counting to probability

Once you can count, 9.B.1’s rule works on big problems: P = favourable ÷ total. Guessing a 4-digit PIN in one try: 1/10,000. Three coins: 2 × 2 × 2 = 8 outcomes, and exactly two heads happens in 3 of them (HHT, HTH, THH), so P = 3/8. A team of 2 picked at random from 5 friends contains both Ana and Ben with probability 1/10, because that’s one team out of ten.

A computer can check a count by listing everything, which is how you test a formula:

from itertools import permutations, combinations   # tools that list arrangements and groups
friends = ['Ana', 'Ben', 'Cy', 'Dee', 'Eli']          # the 5 people to choose from
ordered = list(permutations(friends, 2))              # every (first, second) pair: order matters
teams = list(combinations(friends, 2))                # every pair as a group: order doesn't
print(len(ordered), len(teams))                       # 20 10: each team was counted twice in order

6Traps

Compare

Easy to get wrong

✕ Adding instead of multiplying

3 shirts and 2 pants is not 3 + 2 = 5 outfits. Each shirt goes with every pair of pants: 3 × 2 = 6. Add only when you pick one thing from either list (a shirt or a pair of pants: 5 ways).

✕ Counting a group twice

For a team, Ana-then-Ben and Ben-then-Ana are the same team. 5 × 4 = 20 counts each pair twice: there are 20 ÷ 2 = 10 teams. Ask “does order matter?” before you count.

✕ Forgetting nothing repeats

Gold, silver, bronze from 8 runners is not 8 × 8 × 8 = 512: that would let one runner win all three medals. Each medal leaves one fewer runner: 8 × 7 × 6 = 336.

7Now, in symbols

Here n is the number of things to choose from and k the number of slots, exactly as in the slots explorer.

\[ \text{multiplication principle: } m \times n, \qquad \text{codes (repeats allowed): } n^k \]
\[ n! = n \times (n-1) \times \cdots \times 2 \times 1, \qquad 0! = 1 \]
\[ \text{arrangements (order matters): } P(n, k) = n \times (n-1) \times \cdots \times (n-k+1) = \frac{n!}{(n-k)!} \]
\[ \text{groups (order doesn't matter): } \binom{n}{k} = \frac{P(n,k)}{k!} = \frac{n!}{k!\,(n-k)!}, \qquad \binom{n}{k} = \binom{n-1}{k-1} + \binom{n-1}{k} \]

9Words to know

Systematic listA list made in a fixed order so nothing is missed or repeated.
Two-way tableA grid with one choice down the side and another across the top.
Tree diagramBranches for each option at each stage; each path is one outcome.
StageOne step of the choice: shirt, then pants, then shoes.
Multiplication principlem ways, then n ways: m × n ways in all.
With / without repetitionWhether a symbol or person can be used again.
Arrangement (permutation)An ordering of things, where order matters.
Order mattersAB and BA count as different (a podium, a code).
Factorialn! = n × (n − 1) × … × 1, the number of ways to order n things.
CombinationA group chosen where order doesn’t matter (a team, pizza toppings).
n choose kThe number of groups of k from n, written (n over k).
Pascal’s triangleThe triangle of “choose” numbers; each is the sum of the two above.
