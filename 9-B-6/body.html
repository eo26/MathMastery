Chapter 9 · Probability

Simulating Chance

When a probability is too hard to count, let a computer play the game thousands of times and count how often things happen. More trials give a better estimate, but only slowly: 100 times the trials buys about 10 times the accuracy.

Basics you are here Undergraduate Masters

On this page

  • Build a simulation: a model of each random piece, run as one trial, repeated many times.
  • Turn the results into an estimate of a probability (how often) or an expected value (the average).
  • See how the typical error shrinks as the number of trials grows, roughly like 1/√n.
  • Use the Monte Carlo method, random darts, to estimate π and areas with no simple formula.

1When counting gets hard

How likely is it that two people in a class of 23 share a birthday? How many cereal boxes does it take to collect all six toys? Counting every case is possible but tricky. There’s another way: play it out. A computer can “roll” a 365-sided die for each of 23 people, check for a match, and repeat that 10,000 times in a blink. If a match turned up in about half of those classes, the probability is about ½. (It is: 0.507.)

A simulation needs a model: a way to produce each random piece with a random tool. A birthday is a random whole number from 1 to 365. A 70% free throw is a random number between 0 and 1 that counts as a make when it’s below 0.7. The computer’s source of these numbers is a random number generator. It is really pseudo-random: a clever formula whose output looks random and passes every test of randomness, starting from a number called the seed. The same seed replays exactly the same “random” run, which is handy for checking work.

2The recipe

1. Model each random piece. 2. Run one trial of the whole situation and record what happened. 3. Repeat many times. 4. The fraction of trials where the event happened estimates its probability; the average of a recorded number estimates its expected value. That’s just the relative frequency and long-run average from 9.B.1 and 9.B.5, with a computer doing the tedious part. Each problem below has an exact answer (found by cleverer counting), drawn as a purple line, so you can watch the estimate close in on it.

3How many trials is enough?

An estimate from a simulation is never exact, and running it again gives a slightly different answer. The question is how far off it typically is. After n trials, the typical error of an estimated probability p is about

\[ \text{typical error} \approx \sqrt{\frac{p(1-p)}{n}}, \]

which shrinks like 1/√n. Four times the trials halves the error; a hundred times the trials cuts it to a tenth. With 100 trials an estimate near ½ is typically off by about 0.05; with 10,000 trials, by about 0.005. Accuracy is cheap at first and expensive later. In the lab above, the purple band narrows exactly this way, and the teal line usually stays inside it.

4Random darts: the Monte Carlo method

Simulation can find areas too. Throw darts at random into a square of known area. The fraction that lands inside a shape estimates the shape’s share of the square. A circle of radius 1 inside a 2-by-2 square takes up π/4 of it, so π ≈ 4 × (fraction inside). Methods that answer a question with random sampling are called Monte Carlo methods, after the famous casino. They were named in the 1940s by scientists who used them to design the first nuclear reactors, and today they estimate everything from the area under a bell curve to the light bouncing around a film scene.

5The birthday problem in Python

Here is the whole birthday simulation. The answer surprises most people: with only 23 people, a shared birthday is more likely than not, because there are 253 different pairs who could match.

import random                                          # Python's random-number tools
random.seed(1)                                         # fix the seed so the run can be repeated exactly
trials = 10_000                                        # how many classes to simulate
matches = 0                                            # classes where two people share a birthday
for _ in range(trials):                                # one trial = one class of 23
    birthdays = [random.randint(1, 365) for _ in range(23)]   # model: each birthday is 1 to 365
    if len(set(birthdays)) < 23:                       # a set drops repeats; fewer than 23 means a match
        matches += 1                                   # record the event
p_hat = matches / trials                               # the estimate: about 0.507
error = (p_hat * (1 - p_hat) / trials) ** 0.5          # typical error: about 0.005
print(p_hat, "+/-", error)

6Traps

Compare

Easy to get wrong

✕ Trusting a handful of trials

Ten trials of a 50–50 event can easily give 3 or 7 successes. Here are 20 separate 10-trial estimates of P = ½: they range widely. Small simulations are rough guesses.

✕ A model that doesn’t match

Simulating a 70% free-throw shooter with a coin flip assumes 50%. Every trial is then wrong in the same direction, and more trials only make the wrong answer look more certain.

✕ Treating the estimate as exact

Five runs of 1,000 trials for the birthday problem give five different answers. A simulation gives an estimate with a typical error; it doesn’t prove the exact value.

7Now, in symbols

Run n independent trials. If the event happens in k of them, and a recorded number takes the values x₁, …, xₙ:

\[ \hat p = \frac{k}{n} \approx P(\text{event}), \qquad \bar x = \frac{x_1 + x_2 + \dots + x_n}{n} \approx E(X) \]
\[ \text{typical error of } \hat p \approx \sqrt{\frac{\hat p\,(1-\hat p)}{n}}, \qquad \text{typical error of } \bar x \approx \frac{s}{\sqrt n} \]
\[ \text{Monte Carlo area: } \text{area} \approx (\text{area of the board}) \times \frac{\text{darts inside}}{\text{darts thrown}} \]

Here s is how spread out the individual results are (the standard deviation, 10.B). The hat on p̂ marks an estimate. The law of large numbers (9.U.7) guarantees p̂ and x̄ close in on the true values as n grows; the central limit theorem explains the 1/√n.

9Words to know

SimulationImitating a random situation with random numbers, over and over, to learn its probabilities.
ModelThe rule that produces each random piece (a birthday = random number 1–365).
TrialOne complete run of the simulated situation.
Number of trialsHow many times the simulation is repeated, n.
EstimateA value worked out from the trials: p̂ = k/n, or the average x̄.
Typical errorHow far an estimate is usually off: about √(p(1 − p)/n) for a probability.
Random number generatorThe tool that produces random numbers for a simulation.
Pseudo-randomMade by a formula but behaving as if random.
SeedThe starting number for a pseudo-random generator; the same seed repeats the same run.
Monte Carlo methodAnswering a question (an area, a probability) with random sampling.
Relative frequency / long-run averageFrom 9.B.1 and 9.B.5: what a simulation measures.
